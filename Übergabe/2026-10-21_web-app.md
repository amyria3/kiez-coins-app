# Web-App fürs iPhone

- **Stand:** 21.10.2026
- **Zweck:** iPhone-Testerinnen nutzen Kiez Coins ohne App Store und ohne Apple-Developer-Konto. Die App läuft als Web-App in Safari und liegt nach „Zum Home-Bildschirm“ wie eine App auf dem iPhone.
- **Gehört nach:** Documentation › `kiez-coins/app/Stand_App.md` (Launch-Schritte, Web-App) und `kiez-coins/ENTSCHEIDUNGEN.md` (iPhone über Web-App bis TestFlight).
- **Arbeitsteilung:** Claude hat Web-Build, Dialoge, Standort im Browser und die Download-Seite gebaut. Daria baut die Seite auf dem Mac, lädt `website/` bei Cloudflare Pages hoch und testet auf dem iPhone.

## So ist die Web-App aufgebaut

- Expo baut dieselbe App für den Browser (`web.output: "single"` in `app.json`).
- Die Web-App liegt unter `https://kiezcoins.de/app/`, im selben Cloudflare-Pages-Projekt wie die Download-Seite. Den Pfad setzt `npm run build:website` (Variable `EXPO_WEB_BASE_URL`, ausgewertet in `app.config.js`), nur für den Web-Build. Expo Go und die Android-App bleiben unberührt. Derselbe Pfad steht in `public/index.html` und `public/manifest.json`. Wer den Pfad ändert, ändert alle drei Stellen.
- `public/index.html` enthält die Angaben für den Home-Bildschirm: Name, Icon (`public/apple-touch-icon.png`), Vollbild ohne Browserleiste, dunkle Statusleiste.
- Die Download-Seite zeigt unter „iPhone“ den Button „Kiez Coins öffnen“ und die Schritte für den Home-Bildschirm. Sobald es einen TestFlight-Link gibt, ersetzt er diesen Abschnitt (`testflightUrl` in `scripts/download-site.config.json`).
- `website/app/` entsteht beim Bauen und liegt nicht im Repo.
- Neuladen auf einer Unterseite (`/app/challenge/…`) klappt über `website/app/404.html`, eine Kopie der App-Startseite. Cloudflare Pages liefert bei unbekannten Adressen die nächstgelegene `404.html` aus. Die neue `website/404.html` sorgt dafür, dass unbekannte Adressen außerhalb von `/app/` eine Fehlerseite zeigen.

## Was im Browser anders läuft

- **Anmeldung:** E-Mail mit Passwort und Code per Mail funktionieren unverändert. Die Sitzung liegt im Speicher des Browsers. Die Web-App auf dem Home-Bildschirm hat einen eigenen Speicher, deshalb meldet man sich dort einmal neu an.
- **Fotos:** Safari bietet beim Tippen auf „Foto hinzufügen“ selbst „Foto aufnehmen“, „Fotomediathek“ und „Datei auswählen“ an. Der Upload nutzt denselben Weg wie die App.
- **Rückfragen:** `Alert.alert` ist im Browser leer. `src/components/WebAlert.tsx` ersetzt ihn dort durch einen eigenen Dialog im Stil der App. Die Screens bleiben unverändert, iOS und Android zeigen weiter die Systemdialoge.
- **Standort:** Safari fragt beim ersten Mal nach der Freigabe. expo-location kann im Browser keine Adresse zur Position finden. Die Web-App fragt deshalb Nominatim von OpenStreetMap und schickt dafür nur den auf rund 100 m gerundeten Punkt. Die Datenschutzerklärung nennt das.
- **Push-Benachrichtigungen:** gibt es in der Web-App nicht. Die App hat bisher auch auf Android keine Push-Benachrichtigungen.
- **Updates:** kommen automatisch. Nach jedem Hochladen von `website/` lädt die Web-App beim nächsten Start den neuen Stand.

## Das macht Daria

1. Seite und Web-App bauen (Mac, Terminal im Ordner `kiez-coins-app`):
   ```sh
   git pull
   npm install
   npm run build:website
   ```
2. Den ganzen Ordner `website/` bei Cloudflare Pages hochladen (Schritt 4 in `2026-10-21_download-seite.md`).
3. Auf dem iPhone in Safari `https://kiezcoins.de` öffnen, „Kiez Coins öffnen“ tippen, über Teilen › „Zum Home-Bildschirm“ ablegen und vom Home-Bildschirm aus anmelden, eine Challenge mit Foto anlegen und den Standort testen.

Lokal im Browser ansehen: `npx expo start --web`.

## Getestet

- Export für den Browser läuft, `tsc` ohne Fehler.
- In Chromium mit iPhone-Größe: Download-Seite, App-Start, Neuladen auf einer Unterseite, Rechtstexte in der App und der neue Dialog. Supabase war aus der Testumgebung nicht erreichbar. Anmeldung, Foto-Upload und Standort sind deshalb auf einem echten iPhone zu prüfen.

## Offene Punkte

- Die Web-App ist unter `/app/` für alle erreichbar, die die Adresse kennen. Suchmaschinen schließt `noindex` aus. Ein Konto anlegen kann bei Supabase ohnehin jede Person mit dem öffentlichen Schlüssel.
- Das App-Icon ist noch der Expo-Platzhalter. Nach einem neuen `assets/icon.png` die drei Icons in `public/` neu erzeugen (180, 192 und 512 Pixel).
- Nominatim erlaubt höchstens eine Anfrage pro Sekunde. Für die Testphase reicht das, für einen größeren Start braucht es einen eigenen oder bezahlten Dienst.
